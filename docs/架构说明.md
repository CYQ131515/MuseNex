# MuseNex 架构说明

面向后续迭代的框架文档：外壳、工作区、协议、桥接、构建、扩展约定。

---

## 1. 设计目标

1. **一个应用，多个工作区**：参考板、无限画布、以后新增的能力（素材库、批量处理、3D 参考等）都作为工作区接入，共享窗口、主题、菜单与文件系统能力。
2. **工作区自治**：每个工作区目录保存自己的运行代码与算法文档（`PureRef-CYQ/ALGORITHM.md`、`infinite-canvas/WORKSPACE.md`），外壳不掺入具体业务。
3. **零第三方依赖**：不依赖 npm 包；运行时就是 Electron 内置能力，源码直接可读可改。
4. **可复现构建**：`scripts/build-app.mjs` 从源码组装 `Resources/app`，不动 Electron 运行时；`scripts/check.mjs` 做静态检查。
5. **数据不藏在代码里**：设置、场景、API 密钥都在 `~/Library/Application Support/MuseNex/`。

## 2. 进程与目录

```
┌────────────────────────────────────────────────────────────┐
│ Electron 主进程  shell/main.js                              │
│  ├─ BrowserWindow（主工作区，kind=main，参考板渲染层）        │
│  ├─ WebContentsView × N（视图工作区，kind=view，无限画布…）    │
│  ├─ 自定义协议 musenex://<workspaceId>/…                    │
│  ├─ /api/* 代理（按工作区 manifest 的 apiProxy 配置）        │
│  ├─ 菜单（由工作区清单生成）与 IPC                           │
│  └─ 场景容器 .prcyq 读写 / 自动保存 / 最近文件               │
└───────────────▲───────────────────────────▲────────────────┘
                │ window.musenex (contextBridge)             │ window.__muse*（视图工作区）
     PureRef-CYQ/renderer                   infinite-canvas/dist
     （参考板：store/render/interact/ui）    （节点画布：src 构建产物）
```

| 目录 | 责任 | 不该放什么 |
| --- | --- | --- |
| `shell/` | 窗口、工作区生命周期、协议、菜单、IPC、文件对话框、场景容器 | 具体画布业务逻辑 |
| `PureRef-CYQ/` | 参考板模型、渲染、交互、UI、算法 | 其他工作区代码 |
| `infinite-canvas/` | 无限画布源码、算法、构建、测试 | 外壳逻辑 |
| `scripts/` | 开发、构建、运行时引导、安装、检查 | 运行时代码 |
| `docs/`、`assets/`、`examples/` | 文档、资源、示例 | — |

## 3. 工作区清单 `muse.config.json`

| 字段 | 说明 |
| --- | --- |
| `app.name/version/bundleId/icon` | 应用身份；构建脚本用它更新 Info.plist/图标 |
| `mainWorkspace` | 哪个工作区作为 BrowserWindow 主页面 |
| `workspaces[].id` | 唯一 id，也是 `musenex://<id>/` 的 host |
| `kind` | `main`：主页面；`view`：WebContentsView |
| `dir` | 相对仓库根的工作区目录 |
| `entry` | 入口 HTML（相对 `dir` + `webRoot`） |
| `webRoot` | 可选，静态根（画布为 `dist`） |
| `preload` | preload 相对仓库根的路径 |
| `name/shortcut/shortcutLabel/icon` | 菜单项、快捷键、工具栏图标 |
| `description` | 介绍文本（设置/关于可用） |
| `capabilities` | `addImages` / `pullImages` 等桥能力 |
| `apiProxy` | `{ configFile, baseUrlDefault, envKey, envBase }`，为视图工作区提供 `/api/*` 代理 |

菜单「工作区」、`⌘1/⌘2`、参考板工具栏按钮、切换逻辑都由清单生成，新增工作区无需改外壳代码（除非要新的桥能力）。

## 4. 工作区生命周期

**主工作区**

1. `app.whenReady()` → 读取清单 → 迁移旧数据；
2. 创建 BrowserWindow，`preload` = 清单里的 `shell/preload-main.js`，加载 `PureRef-CYQ/renderer/index.html`；
3. 渲染层通过 `window.musenex` 使用 IPC；`initWorkspace()` 拉取工作区列表并注册动态动作；
4. 完整原生菜单（文件/编辑/图片/模式/画布/工作区/窗口）。

**视图工作区**

1. 首次切换时 `ensureView(ws)`：创建 WebContentsView（preload = 清单 preload，`additionalArguments` 带 `--muse-workspace=<id>`）；
2. 加载 `musenex://<id>/<entry>`；协议处理器从 `dir[/webRoot]` 提供静态文件，`/api/*` 走代理；
3. `did-finish-load` 后标记 ready，同步主题；
4. 附加到主窗口 `contentView` 并铺满内容区；切换走时 `removeChildView`（不销毁，保留页面状态）；
5. 视图 preload 注入红黄绿窗控、返主按钮、能力按钮与边缘缩放；页面内自定义桥由工作区提供。

**切换语义**

- `setWorkspace(id)`：保存到 settings、附加/移除视图、更新标题、重建菜单、通知主渲染层
  `workspace-changed`；
- 同 id 重复切换是幂等的；
- 关闭窗口不销毁缓存视图；退出应用统一释放。

## 5. 协议 `musenex://`

- 注册为 `standard + secure + supportFetchAPI + corsEnabled + stream`，因此工作区拥有稳定的
  origin（localStorage 不会因端口变化丢失），且 `/api/*` 与页面同源，无需 CORS。
- 路径解析：`<workspace.dir>/<webRoot>/<pathname>`；越界路径拒绝。
- 只有清单里声明了 `apiProxy` 的工作区才会代理 `/api/*`：
  - `/api/health` 特判（检查上游 `/models`，返回 `{ok,hasKey,base,models,keySource}`）；
  - 其余请求按方法/Content-Type/二进制透传，附加 `Authorization: Bearer <key>`；
  - 密钥读取顺序：环境变量 → `userData/<configFile>`；不下发到页面。

新增视图工作区时，直接在清单里配 `apiProxy` 就能复用该代理。

## 6. 桥接 API

### 6.1 主工作区 → 外壳（`window.musenex`）

| 命名空间 | 能力 |
| --- | --- |
| `app` | `info/relaunch/quit` |
| `settings` | `get/set` |
| `workspace` | `list/get/set/onChanged/onViewImages` |
| `view` | `addImages(items,targetId) / pullImages(targetId) / syncTheme(theme)` |
| `win` | 最小化/最大化/关闭/置顶/透明度/穿透/拖动/缩放/多窗口 |
| `dialog` | 打开图片/场景、保存场景、选目录、保存文件 |
| `fs` | 读写文件、`.prcyq` 读写、自动保存、stat/list |
| `clipboard` | 图片/文本读写 |
| `shell` | 打开路径/外链 |
| `onMenu / onOpenPath` | 菜单动作、文件关联打开 |

### 6.2 视图工作区 → 外壳（`shell/preload-view.js`）

通用（所有视图工作区自动拥有）：

- `window.__museSetTheme(theme)`：暗/亮同步；
- 窗口：`view:win`（close/minimize/maximize）、`view:show-main`、`view:resize-*`；
- 注入 UI：红黄绿窗控、`← 返回主工作区`、按 `capabilities` 显示 `⤓ 取图`；
- `-webkit-app-region: drag` 绑定画布标题栏，实现无边框拖动。

工作区自定义：

- `window.__museAddImages(items)`：`items = [{name, dataUrl}]`，由工作区自行落到自己的模型；
- `window.__musePullSelected()`：返回 `[{name, dataUrl}]`，外壳转交主工作区；
- 旧命名 `__prcyq*` 保留别名，避免历史页面失效。

### 6.3 图片互传时序

```
参考板选中图片
  → P.sendSelectionToView(targetId)
  → IPC view:add-images(items, targetId)
  → 主进程找到/创建目标 WebContentsView
  → executeJavaScript(__museAddImages) → 工作区生成节点
  → toast

视图工作区选中图片
  → 点击 ⤓ → __musePullSelected() → IPC view:pulled-images
  → 主进程转发主窗口 view-images
  → 参考板 addViewImages() → 插入图片项
```

## 7. 数据与存储

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 设置 | `userData/settings.json` | 窗口位置、主题、快捷键、最近文件、当前工作区 |
| 场景 | 用户选择路径 `.prcyq` | 单文件容器：`PRCYQ1\n` + uint32 JSON 长度 + JSON 头 + 图片二进制段 |
| 自动保存 | `userData/autosave.prcyq` | 崩溃/重启恢复 |
| 画布 API | `userData/canvas-config.json` | `{ apiKey, baseUrl }`，不打包进 app |
| 画布文档 | 画布 origin 的 localStorage | 由无限画布自身管理；可 JSON 导入导出 |
| 旧版迁移 | `appData/PureRef-CYQ/` → `userData` | 首次启动自动复制 settings/canvas-config/autosave |

## 8. 构建与发布

```
scripts/build-app.mjs
  0. 若缺少 .runtime/MuseNex.app：调用 scripts/bootstrap-runtime.mjs 下载并准备运行时
  1. 停止运行中的 MuseNex
  2. 清空 .runtime/MuseNex.app/Contents/Resources/app
  3. 复制 package.json / muse.config.json / shell/*.js
  4. 按清单复制：主工作区 renderer（+package.json）；视图工作区 webRoot 产物
  5. 由 assets 图标源生成 MuseNex.icns；更新 Info.plist 版本/文档类型
  6. codesign --force --deep --sign -
  7.（--install）ditto 到 /Applications/MuseNex.app、注册 LaunchServices、刷新 Dock
```

开发模式不需要构建：

```bash
./scripts/dev.command
# 等价于：
# .runtime/MuseNex.app/Contents/MacOS/MuseNex <仓库根> \
#   --user-data-dir="$HOME/Library/Application Support/MuseNex-dev" --remote-debugging-port=9222
```

外壳通过 `__dirname/..` 解析仓库根，因此同一份 `shell/main.js` 既能在源码目录跑，也能在
`Resources/app/shell/` 里跑——这也是构建脚本只需要复制文件的原因。

## 9. 扩展指南

### 新增功能（现有工作区）

1. 参考板：`store.js` 加状态/算法 → `render.js` 加绘制 → `interact.js` 加手势 → `ui.js` 加界面/动作 → `i18n.js` 注册 id 与默认快捷键；
2. 画布：在 `infinite-canvas/src/` 修改 → `node build.mjs` → 重新构建安装；
3. 涉及外壳能力（新对话框、系统能力）时在 `shell/main.js` 加 IPC，并在对应 preload 暴露；
4. 运行 `node scripts/check.mjs`，再 `./scripts/install.sh`。

### 新增工作区

1. 建目录 `NewWorkspace/`（代码 + `ALGORITHM.md` + 可选 `package.json`）；
2. `muse.config.json` 增加条目：`kind: "view"`、`dir`、`entry`、`preload`、`shortcut`、`icon`、`capabilities`；
3. 若需图片互传，实现 `__museAddImages/__musePullSelected` 并声明 capabilities；
4. 若需外部 API，加 `apiProxy`；
5. `node scripts/check.mjs && node scripts/build-app.mjs --install`。

### 约定

- 目录名保持稳定（文档/脚本/数据迁移都依赖）；工作区代码不互相 import；
- 所有跨进程能力必须经 preload 暴露的窄接口，不在渲染层直接 require；
- 新存储写到 `userData`，不写仓库；
- 文档与代码同目录（每个工作区一份算法说明），架构变更同步本文件与 README。
