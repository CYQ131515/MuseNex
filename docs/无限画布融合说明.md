# 双工作区融合说明（MuseNex）

MuseNex 是一个**双工作区**应用：同一个窗口、同一个 `.app`，`⌘1` 参考板 / `⌘2` 无限画布，共享主题与图片互通。

| 工作区 | 内容 | 快捷键 |
| --- | --- | --- |
| **参考板** | PureRef 风格的无限图片画布（原 `PureRef-CYQ` 工程） | `⌘1` |
| **无限画布** | 节点式 AI 工作流画布（`infinite-canvas` 工程构建产物） | `⌘2` |

两个工作区互相独立、各自保存数据；图片可以在两边互发。

---

## 1. 架构

```
MuseNex/
├── shell/
│   ├── main.js           统一外壳：窗口、工作区注册/切换、musenex:// 协议、菜单、IPC、.prcyq 容器
│   ├── preload-main.js   参考板桥（window.musenex）
│   └── preload-view.js   视图工作区桥（窗控、主题、图片互传、边缘缩放）
├── PureRef-CYQ/renderer  参考板模型/渲染/交互/UI
├── infinite-canvas/
│   ├── src/              画布源码与算法
│   └── dist/             单文件构建产物（外壳实际加载）
├── muse.config.json      工作区清单（菜单/快捷键/协议/桥能力都由它生成）
├── MuseNex.app           安装后的启动程序（/Applications）
└── .runtime/MuseNex.app  构建用运行时（隐藏）
```

为什么用 `WebContentsView`：无限画布是完整的独立 Web 应用，放在独立渲染进程里可以原样保留
它自己的快捷键、框选、拖拽和 localStorage。自定义协议 `musenex://<workspaceId>/…` 提供稳定
origin（画布数据不会因端口变化丢失），并让 `/api/*` 与页面同源，无需 CORS。

## 2. 切换与窗口

- `⌘1` / `⌘2`，或菜单「工作区」/「窗口」；参考板底部工具栏也有工作区按钮。
- 画布工作区左上角注入 macOS 风格红黄绿窗控；标题栏空白处可拖动窗口，双击最大化。
- 画布工作区四周 7px 可拖动缩放窗口（由 `shell/preload-view.js` 接管，与参考板体验一致）。
- 右上角两个图标：
  - `←` 返回主工作区（参考板）
  - `⤓` 把选中的图片节点发送到参考板（仅声明了 `pullImages` 能力的工作区显示）
- 首次进入视图工作区会提示返回入口。
- 应用记住上次所在工作区；删除 `~/Library/Application Support/MuseNex/settings.json` 可重置。

## 3. 图片互通

**参考板 → 无限画布**

1. 参考板选中一张或多张图片；
2. 点工具栏「发送到…」图标，或右键菜单 / 菜单「图片 → 查看工作区 → 发送选中图片」；
3. 画布在当前视图中心创建图片节点（多张自动错开）。

实现：参考板 `blobToPng` → dataURL → IPC `view:add-images(items, targetId)` → 主进程对目标
`WebContentsView` 执行 `window.__museAddImages()` → 构造 `File` 并触发画布自身 `drop-files`
流程（等价于把图片拖进画布）。

**无限画布 → 参考板**

1. 画布选中一个或多个含图片的节点；
2. 点右上角 `⤓`；
3. 参考板把图片作为新参考图插入当前场景中心。

实现：`shell/preload-view.js` 读取节点 `data.media`，`fetch` 成 dataURL（远程资源失败时回退
canvas 绘制），通过 IPC `view:pulled-images` 转交主进程 → 参考板 `addViewImages()` 插入。

> 只处理图片节点；视频/音频暂不传输。远程媒体若被防盗链拦截会提示导出失败。

---

## 4. 主题与外观

- 参考板切换暗/亮/玻璃主题时，同步给所有视图工作区（`__museSetTheme`，只区分 dark/light）。
- 画布自己的主题按钮仍然可用，但只影响画布，不回传参考板。

---

## 5. AI / APIMart 配置

画布的生成能力通过主进程代理访问 APIMart，密钥**不写进 app 包**：

```
~/Library/Application Support/MuseNex/canvas-config.json
{
  "apiKey": "sk-…",
  "baseUrl": "https://api.apimart.cn/v1"
}
```

也可用环境变量 `APIMART_API_KEY` / `APIMART_BASE_URL`。未配置时画布仍可正常编辑节点、连线、
导入导出，只是生成类节点提示未配置。

代理端点（与 infinite-canvas 原工程一致）：`/api/health`、`/api/models`、`/api/balance`、
`/api/chat`、`/api/images`、`/api/videos`、`/api/tasks/:id`、`/api/audio/speech`、
`/api/uploads/images`。配置由 `muse.config.json` 里画布工作区的 `apiProxy` 声明，可由新工作区复用。

## 6. 更新无限画布

```bash
cd infinite-canvas
node build.mjs                  # 重新生成 dist/infinite-canvas.html
cd ..
node scripts/build-app.mjs --install   # 重新组装 Resources/app、签名并安装
```

开发时用 `./scripts/dev.command` 直接以仓库源码运行，改 `src/` 后需先 `node build.mjs`。

---

## 7. 已知限制

1. 两个工作区**数据彼此独立**：参考板 `.prcyq`，画布 localStorage + JSON 导入导出；暂无“双工作区打包”格式。
2. 原 infinite-canvas 项目的数据在浏览器 `file://` origin 下；迁移请用画布「导出画布 JSON」→ 在 MuseNex 画布中导入。
3. 画布工作区内右键是它自己的框选/平移；移动窗口请拖标题栏，或 `⌘F` 最大化。
4. 画布 AI 生成依赖 APIMart 网络与额度；离线可用节点编排、图片导入与参考板互传。
